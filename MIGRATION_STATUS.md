## Audit (Stage 0)

### Architecture today
- `index.html` (3.4 MB) is GENERATED by `tools/build.py` from `tools/src/index.base.html` (15 original systemic topics, hand-written HTML+JS) plus `tools/content.py` (+ `gp_written*.txt`, `box_viva.txt`, `answers.md`, `answers_by_id.json`, `hand_edits.json`, `robbins_outline.py`, `robbins_map.py`, `dupmerge.py`, CSS/JS fragments in `tools/*.css|js`).
- build.py works by string-replacing inside the base HTML, then shells out to idempotent post-passes that edit the generated `index.html` in place: `apply_answers_by_id.py`, `format_answers*.py`, `fix_numbering.py`, `split_semicolons.py`, `apply_hand_edits.py`, `source_links.py`. `ui_patch.py` and `nav_patch.py` are imported and patch the HTML string. These are the "Python scripts that patch application code" (Stage 7); `apply_hand_edits.py`/`hand_edits.json` hold edits that exist nowhere else (content, must be ported not dropped).
- All 1,310 question cards and answers are inline in `index.html` as `<article class="card" id="qN">`; a `DATA` array and `QMETA` object are inline JS. The search index is built from the DOM.
- Textbook: `textbook/chNN.html` (29 chapters, fragments) + `textbook/index.json`, loaded on demand by `tools/textbook.js` (inlined). Sources `tools/textbook_src/chNN.json`, builder `tools/textbook_build.py`.
- MCQs: `tools/mcq.js` + `tools/mcqs.json` (inlined), sources `tools/mcq_src`, parser `tools/mcq_parse.py`.
- Annotations: `annot/annot.js` (140 KB) + `annot.css`, own IndexedDB.
- `welcome.js` loaded separately (first-run name prompt/banner).
- Service worker `sw.js`: hand-versioned (`VERSION = 'pathviva-zzee-v159'`), hand-listed `CORE` precache, textbook precache in `activate`, cache-first for assets, network-with-2.5 s fallback for navigations, deletes older `pathviva-*` caches.

### Storage keys and shapes (preserve; versioned/migratable in Stage 3)
localStorage:
- `vivaState` JSON: `{fav:[qid], bm:[qid], notes:{qid:string}, learned:[qid], sr:{qid:{d:ts,...}}, streak:{n,last}, recent:[...], pref:{fs,focus,...}, mcq:{p,o,rd,nt,day (objects); bm,hist,rv,ms (arrays)}}`
- `vivaStatePrev` (previous state kept before a restore), `vivaStateCorrupt` (unreadable state kept instead of overwritten)
- `tbDone` JSON `{chapterId: 1}`, `tbPos` JSON `{chapterId: scrollFraction}`, `tbLast` string (last chapter id)
- `vivaQuiz` ('1' or ''), `zz-fs`, `zz-flat` (UI prefs), `zzName` (first-run name)
- Alias migration: `QALIAS` moves fav/bm/learned/sr/notes/annotations from merged-away cards to survivors on load.
IndexedDB:
- `pathviva-annot` v1: object stores `docs` (keyPath `k`, records `{k:'q:<cardid>'|..., objs:[...]}`) and `meta` (keyPath `k`, e.g. `{k:'prev', v:{at,data}}`)
- `pathviva-ink`: legacy, read-only fallback
Backup/restore: file `patholo_zzee-backup-*.json` = `vivaState` + `annot` (old backups with `ink` still restore); restore is validated (`vbk`), keeps previous state, rolls back on failure.

## Decisions
- D1: Python `jsonschema` (dev-only, already installed here, no runtime effect) is used to validate generated JSON against schemas in the integrity script. Benefit: schema validation is a stated requirement; hand-rolling a validator would be larger and less reliable. Not shipped to users.
- D2: Differential integrity script compares a content manifest extracted from the legacy `index.html` (plus `textbook/`, `source_map.json`) against one extracted from the Vite build. To stay under 1 minute, the legacy build is not rerun by default: the script verifies the committed legacy output is fresh by content-hashing the sources, and offers `--rebuild-legacy` (about 3 min) for a full same-commit comparison. Final stage runs it with `--rebuild-legacy`.
